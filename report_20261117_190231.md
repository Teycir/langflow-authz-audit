## 1. Executive Summary

### 1.1 Background
Objective: find a non-obvious logic/state/privilege flaw in Langflow, prioritising cross-tenant (IDOR) and privilege-escalation paths over generic scanner findings, with a triage-proof, non-destructive PoC. Static audit of the public/unauthenticated surface had already excluded the known CVE classes (CVE-2025-3248 unauthenticated code exec, CVE-2026-33017 public build, GHSA-rcjh-r59h-gq37 MCP composer exposure). This engagement therefore stood up the application with two independent principals and executed a differential authorization matrix against a victim tenant's flows, files, folders, MCP projects, traces, variables and knowledge-base storage.

### 1.2 Overall Posture
**No bounty-grade vulnerability was confirmed.** Every cross-tenant data read/execute attempt was denied (403/404) while owner controls succeeded; the API-key execution path (`/run/*`, `/webhook*`) is likewise user-scoped. Three low-value defects were confirmed, all of the same systemic class: **broad `except Exception` handlers convert authorization denials (404) into 200 or 500 responses**, producing inconsistent authorization signals and leaking internal error text. Root cause is symptomatic of exception-handling discipline in `api/v1/mcp_projects.py` and `api/v2/files.py`, not a failure of the permission model itself (`verify_project_access`, `ensure_file_permission` are correct).

## 4. Findings Detail

### RT-01 — Authorization denial (404) swallowed into HTTP 200 in `GET /api/v1/mcp/project/{project_id}/composer-url`

- **Severity:** Informational
- **CVSS 3.1:** 0.0 — `CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:N` (https://www.first.org/cvss/calculator/3.1#CVSS:3.1/AV:N/AC:L/PR:L/UI:N/S:U/C:N/I:N/A:N)
- **CWE:** CWE-755 (Improper Handling of Exceptional Conditions), CWE-209 (Generation of Error Message Containing Sensitive Information)
- **Affected URL/Area:** `GET /api/v1/mcp/project/{project_id}/composer-url`
- **Difficulty to exploit:** Low
- **Authentication required:** Yes (any authenticated user)
- **User interaction required:** No
- **Verified at (UTC):** 2026-11-17T19:01:53Z (initial), 2026-11-17T19:02:01Z (retry), 2026-11-17T19:03:27Z (PoC)

#### Issue Description
`verify_project_access` (`src/backend/base/langflow/api/v1/mcp_projects.py:1798`) filters `Folder.user_id == current_user.id` and raises `HTTPException(404, "Project not found")` for a foreign or unknown project. `get_project_composer_url` wraps the call in a broad `except Exception` and returns HTTP 200 with `error_message="Failed to get MCP Composer URL. See logs for details."` The response for a **foreign project** is indistinguishable from the response for a **project that exists but whose composer is misconfigured**, so clients cannot distinguish "not authorised" from "temporarily broken".

#### Attack Scenario
An authenticated low-privilege user enumerates project UUIDs. For each, a 200 response confirms the UUID is syntactically valid while the generic `error_message` masks whether the project exists or belongs to someone else. This weakens detection/telemetry and any client-side authorization decision that trusts HTTP 200.

#### Steps to Reproduce / PoC
Prereqs: Langflow running at `$BASE`, two accounts (`attacker` non-superuser, `admin` owner), victim project UUID known.
1. Authenticate both users and capture bearer tokens.
2. `GET $BASE/api/v1/mcp/project/<VICTIM_PROJECT>/composer-url` with the **attacker** token → expect `200` + `error_message`.
3. Repeat with a random UUID → same `200` shape.
4. Repeat with the **owner** token → `200` + `uses_composer:false` + real `streamable_http_url`.
5. Run `pocs/reproduce_error_semantics.py` (all checks PASS, exit 0).

#### Request
```http
GET /api/v1/mcp/project/6fc8d7dd-3079-44b0-8383-e82e0789d879/composer-url HTTP/1.1
Host: 127.0.0.1:7860
Authorization: Bearer <attacker-token>
```
#### Response
```http
HTTP/1.1 200 OK
Content-Type: application/json

{"project_id":"6fc8d7dd-3079-44b0-8383-e82e0789d879","uses_composer":true,"streamable_http_url":null,"legacy_sse_url":null,"error_message":"Failed to get MCP Composer URL. See logs for details."}
```
Owner control (`evidence/final_own_composer_victim.http`):
```json
{"project_id":"6fc8d7dd-3079-44b0-8383-e82e0789d879","uses_composer":false,"streamable_http_url":"http://127.0.0.1:7860/api/v1/mcp/project/6fc8d7dd-.../streamable","legacy_sse_url":"http://127.0.0.1:7860/api/v1/mcp/project/6fc8d7dd-.../sse","error_message":null}
```
#### Evidence artifacts
- `evidence/final_atk_composer_victim.http` — sha256 `db0353c919ce86719eb91823969096754cbd53b3dfa43b53f483222e16112ebb`
- `evidence/final_atk_composer_random.http` — sha256 `7c80dedfee236c11fcfdc461914c5bf54b47be04e2ee820afdd3b5b6ab69739b`
- `evidence/final_own_composer_victim.http` — sha256 `9ea5bcc6288ad042e8a04f06516fa2661e89de23b109adc6d7053c0ce5e4268f`
- `evidence/verification-timeline.log` — sha256 `d97d073c33ee4f82e0d583f38563ba7a0abf27c16bcc9553402ef8c3c6612433`

#### Impact
No data disclosed. Impact limited to incorrect authorization semantics (200 for denied access), log-only diagnostics, and possible client misbehaviour. Not bounty-grade.

#### Affected Demographic
All self-hosted Langflow deployments exposing MCP project endpoints to more than one tenant.

#### Recommended Fix
In `get_project_composer_url`, call `await verify_project_access(...)` **outside** the broad `try`, or re-raise `HTTPException` first:
```python
except HTTPException:
    raise
except Exception as exc:
    ...
```
Defence-in-depth: central middleware mapping "permission helper raised 404" to 404 and emitting an audit event.

### RT-02 — `GET /api/v1/mcp/project/{project_id}/installed` returns HTTP 500 for a foreign project

- **Severity:** Informational
- **CVSS 3.1:** 0.0 — same vector as RT-01
- **CWE:** CWE-755
- **Affected URL/Area:** `GET /api/v1/mcp/project/{project_id}/installed`
- **Difficulty to exploit:** Low
- **Authentication required:** Yes
- **User interaction required:** No
- **Verified at (UTC):** 2026-11-17T19:01:53Z, 2026-11-17T19:03:27Z (PoC)

#### Issue Description
`check_installed_mcp_servers` (`mcp_projects.py:~1183`) catches every exception, including the `HTTPException(404)` produced by `verify_project_access`, and re-raises it as a 500 whose body is the stringified denial: `{"detail":"404: Project not found"}`. Authorization failures must not be reported as server errors.

#### Attack Scenario
An attacker diffs 404 vs 500 to infer whether a project UUID exists and is guarded, and obtains internal status text. This is an authz-oracle weakness, not a data leak.

#### Steps to Reproduce / PoC
1. `GET $BASE/api/v1/mcp/project/<VICTIM_PROJECT>/installed` with attacker token → `500 {"detail":"404: Project not found"}`.
2. Repeat with random UUID → identical `500`.
3. Owner token → `200` list of MCP servers.

#### Request
```http
GET /api/v1/mcp/project/6fc8d7dd-3079-44b0-8383-e82e0789d879/installed HTTP/1.1
Host: 127.0.0.1:7860
Authorization: Bearer <attacker-token>
```
#### Response

Content-Type: application/json

### RT-03 — `POST /api/v2/files/batch/` converts a foreign-file 404 into HTTP 500 and echoes internal detail

- **Severity:** Informational
- **CVSS 3.1:** 0.0 — same vector as RT-01
- **CWE:** CWE-755, CWE-209
- **Affected URL/Area:** `POST /api/v2/files/batch/`
- **Difficulty to exploit:** Low
- **Authentication required:** Yes
- **User interaction required:** No
- **Verified at (UTC):** 2026-11-17T19:01:53Z, 2026-11-17T19:03:27Z (PoC)

#### Issue Description
The batch download handler collects per-file errors and wraps them: `{"detail":"Error downloading files: 404: No files found"}` with HTTP 500. `ensure_file_permission` correctly denies foreign files; only the error mapping is wrong. Body must be a raw JSON array (`{"file_ids":[...]}` is rejected 422).

#### Attack Scenario
Attacker submits harvested file UUIDs. Denied and non-existent IDs both return 500 with internal detail, creating a weak existence oracle and leaking implementation strings.

#### Steps to Reproduce / PoC
1. `POST $BASE/api/v2/files/batch/` with attacker token and body `["<VICTIM_FILE_ID>"]` → `500 {"detail":"Error downloading files: 404: No files found"}`.
2. Body `["<RANDOM_UUID>"]` → identical 500.
3. Owner token with the victim file → `200` `application/zip` containing `victim-secret.txt` (`IDOR-VICTIM-SECRET-1794941259`).
